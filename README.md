# 无限画布扫雷

基于 BS 架构的无限画布扫雷游戏。服务端权威生成无限地图并同步状态，前端纯 Canvas 渲染，桌面与移动端触屏均可玩（长按标旗、双指缩放），支持中键预览连锁翻开、道具随机奖励。

## 快速开始

```bash
npm install
npm start          # 默认 http://localhost:8420 ，可用 PORT=xxxx 覆盖
```

浏览器打开 `http://localhost:8420` 即可游戏，无需构建步骤。

### Docker Compose 部署

```bash
docker compose up -d --build     # 默认映射宿主机 8420
HOST_PORT=9000 docker compose up -d   # 自定义宿主机端口
docker compose logs -f / down    # 查看日志 / 停止
```

镜像基于 `node:22-alpine`，以非 root 用户运行，内置 HTTP 健康检查；容器内固定监听 8420，对外端口由 `HOST_PORT` 控制。

## 操作说明

| 操作 | 效果 |
| --- | --- |
| 左键 | 翻开格子；数字上左键为经典 chord（旗数=数字时翻开周围） |
| 右键 | 标旗 / 取消标旗，可按住拖拽连续标旗 |
| 中键（数字格） | 3×3 预览：若周围雷已全部标出或本无雷，自动翻开并连锁扩散空白区域；危险时整片未翻开格显示红色淡化效果（不泄露雷的位置） |
| 按住空格 + 任意键拖拽 | 平移画布 |
| 滚轮 | 以鼠标为中心缩放 |
| 道具栏 | 点选道具后左键在目标格使用，Esc 取消 |

### 移动端触屏（自动检测，无需配置）

| 手势 | 效果 |
| --- | --- |
| 拖拽 | 平移画布 |
| 双指捏合 | 缩放（以双指中点为中心） |
| 双击未翻开格 | 翻开（单击无作用） |
| 长按 | 标旗；再次长按取消标旗 |
| 长按数字格 | 3×3 预览，周围雷标完自动连锁翻开 |
| 点道具图标 → 点目标格 | 使用道具 |

UI 为浮动圆角胶囊风格；移动端窄屏自动排成两行（第一行 标题/生命/统计 + ☰ 菜单靠右，第二行道具条整行横向滑动、隐藏滚动条）。首次进入自动弹出操作提示（之后可从 `☰ 菜单 → 操作说明` 查看），菜单内含“新地图”。

## 游戏规则

- 地图无限：地雷位置由服务端种子哈希确定性生成，密度 14%，可向任意方向无限推进
- 3 条生命，踩雷扣 1；生命归零后结算，可换新种子开新地图
- HUD 实时显示当前视角内未排除雷数、视角内已标旗数、累计翻开格数

## 道具随机奖励

每次成功翻开有 2% 概率掉落随机道具（按权重）：

| 道具 | 权重 | 效果 |
| --- | --- | --- |
| 🛡️ 护盾 | 20 | 被动：踩雷时自动抵消并中和该雷 |
| 🔨 雷锤 | 25 | 左键安全中和一枚雷 |
| 🧲 磁铁 | 25 | 自动标出目标 3×3 内的所有雷 |
| 💣 炸弹 | 20 | 左键安全炸开 5×5 区域 |
| ❤️ 治疗 | 10 | 恢复 1 点生命（上限 5） |

## 架构

```
minesweeper-infinite/
├── server.js        # Node HTTP 静态服务 + WebSocket 服务端（唯一服务端文件）
├── public/
│   ├── index.html   # HUD / 结算界面
│   ├── app.js       # Canvas 渲染 + 交互（无框架、无打包器）
│   └── style.css
└── test/ws-test.js  # WebSocket 协议集成测试（需服务已启动）
```

- **BS 架构**：所有游戏逻辑与地图真值在服务端；客户端仅缓存 `格子坐标 → {状态, 数字}` 并渲染。地雷坐标从不下发（预览响应故意只含坐标与安全性结论）
- **状态同步**：服务端按增量 delta 广播格子变化；格子状态码 `s`：`0` 未翻开 / `1` 已翻开 / `2` 已标旗 / `3` 已中和 / `4` 已爆
- **全局单局**：游戏状态为进程级单例，所有连接共享；`reset` 消息会为新随机种子重建整局
- **静态资源**：响应带 `Cache-Control: no-cache`，避免浏览器启发式缓存旧版前端导致新旧文件混搭

### WebSocket 协议（JSON）

客户端 → 服务端：

| 消息 | 说明 |
| --- | --- |
| `{t:"reveal",x,y}` | 左键翻开 / chord |
| `{t:"flag",x,y}` | 标旗切换 |
| `{t:"preview",x,y}` | 中键 3×3 预览（仅对已翻开数字格响应，150ms 限频） |
| `{t:"prop",prop,x,y}` | 使用道具 |
| `{t:"vp",x0,y0,x1,y1}` | 请求视角范围雷数（单轴上限 600） |
| `{t:"reset"}` | 换新种子重开 |

服务端 → 客户端：

| 消息 | 说明 |
| --- | --- |
| `{t:"cells",d:[[x,y,s,n],…]}` | 格子状态增量 |
| `{t:"hud",lives,score,props,over}` | 状态栏数据 |
| `{t:"preview",d:[[x,y],…],ok}` | 预览结果，`ok=true` 表示已自动翻开（负载不含任何雷/数字信息） |
| `{t:"vpcount",n}` | 视角内雷数 |
| `{t:"drop",prop}` / `{t:"toast",msg}` | 道具掉落 / 提示 |
| `{t:"reset"}` / `{t:"over"}` | 整局重建 / 结算 |

## 测试

```bash
npm start &        # 先启动服务
node test/ws-test.js

# 对 Docker 容器（8421 端口）跑同一套测试
HOST_PORT=8421 docker compose up -d --build
WS_URL=ws://localhost:8421 node test/ws-test.js
```

测试通过 WebSocket 客户端验证：视角雷数统计、预览信息不泄露、chord/连锁翻开、道具接口。每次运行会先 `reset`（注意：会清空所有已连接客户端的当前局）。
